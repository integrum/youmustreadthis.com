## Story

As a crawler,
I want a sitemap and robots.txt,
so that every page is discovered and crawl rules are explicit.

## Acceptance Criteria

1. **Plugin installed.** `jekyll-sitemap` (`~> 1.4`, current release 1.4.0) is in the `Gemfile` inside a `group :jekyll_plugins do ... end` block, `Gemfile.lock` is updated via `bundle install` (keep the existing platforms: `ruby`, `arm64-darwin`, `x86_64-darwin`, `x86_64-linux-gnu`), and `_config.yml` lists it under `plugins:`.
2. **Canonical site URL.** `_config.yml` sets `url: https://youmustreadthis.com` (no trailing slash) and leaves `baseurl` unset or empty, so every `<loc>` in the sitemap is an absolute `https://youmustreadthis.com/...` URL.
3. **sitemap.xml content today.** After `npm run build`, `_site/sitemap.xml` exists, is well-formed XML (sitemaps.org 0.9 `urlset`), and lists exactly `https://youmustreadthis.com/`. It must not list any non-page artifact: nothing from `scripts/`, `docs/`, `img/`, `assets/`, `_bmad/`, `_bmad-output/`, `.agents/`, `.claude/`, `.keeper/`, `node_modules/`, `robots.txt`, or `sitemap.xml` itself.
4. **Future pages included automatically (FR3 forward-compat).** No per-page sitemap edits are required when later stories land:
   - when Story 1.2 sets `collections.books.output: true` with `permalink: /books/:name/`, all 10 books appear as `https://youmustreadthis.com/books/<slug>/`;
   - when Story 2.4 adds an `/about/` page (`about.md` or `about.html` with front matter), it appears as `https://youmustreadthis.com/about/`.
   This is proven in this story with a throwaway config/page overlay (see Task 5) that is not committed.
5. **Non-page files excluded at the source.** `scripts` is added to `_config.yml` `exclude:` (today `scripts/visual-regression/*.mjs` and `pages.json` are copied into `_site/`), and the existing excludes (`docs`, `src`, `node_modules`, etc.) are kept. `_site/` no longer contains a `scripts/` directory.
6. **robots.txt.** A repo-root `robots.txt` is published at `_site/robots.txt` with exactly:
   ```
   User-agent: *
   Allow: /

   Sitemap: https://youmustreadthis.com/sitemap.xml
   ```
   It is a plain static file (no front matter), so jekyll-sitemap's own auto-generated robots.txt is suppressed and the file never appears in the sitemap.
7. **Build stays green.** `npm run build` (run as `mise exec node@22 ruby@3.4.11 -- npm run build`) and `JEKYLL_ENV=production npm run build` both succeed; the Tailwind step still writes `_site/assets/css/style.css` and does not remove `sitemap.xml` or `robots.txt`. `_site/index.html` is byte-identical to a pre-change build (this story touches no templates).
8. **Deploy preview.** On the Netlify deploy preview for the PR, `/sitemap.xml` and `/robots.txt` both return HTTP 200 (check with `curl -sI`), and their bodies match AC 3 and AC 6. Record the preview URL and status lines in the Dev Agent Record.
9. **Docs.** `AGENTS.md` "Where things are" notes that `sitemap.xml` is generated by `jekyll-sitemap` (opt a page out with `sitemap: false` front matter) and that `robots.txt` lives at the repo root; "Known pitfalls" notes that new top-level non-page directories must be added to `_config.yml` `exclude:`.

### jekyll-sitemap behaviour (1.4.0)

- Generates `/sitemap.xml` from `site.html_pages`, every collection doc whose collection has `output: true`, and static files with extension `.html`, `.htm`, `.xhtml`, `.pdf`. It skips anything with `sitemap: false` front matter and skips `404.html`/`/404/`. This is why book pages (Story 1.2) and `/about/` (Story 2.4) get included with no further work, and why `.mjs`/`.json`/images never appear even if copied.
- `<loc>` values use `site.url` + `site.baseurl` via `absolute_url`; without `url` they would be relative/empty, so AC 2 is required. Deploy previews will list production URLs, which is correct (canonical host).
- If no `robots.txt` exists as a page or static file, the plugin auto-generates one containing only `Sitemap: <url>/sitemap.xml`. We ship an explicit file (AC 6) so `User-agent`/`Allow` rules are present; the plugin detects it and does not overwrite it.
- `<lastmod>` appears only for pages/docs with `last_modified_at` or `date`; none exist now. Do not add `jekyll-last-modified-at` in this story.
- Pages can be opted out with `sitemap: false` front matter, or in bulk via `_config.yml` `defaults:` with a `scope.path`. Not needed today; documented in AGENTS.md for future use.

### Plugin loading in Jekyll 4.4

Gems in the `:jekyll_plugins` Bundler group are required automatically when running under `bundle exec`; the `plugins:` list in `_config.yml` is kept as well so the plugin set is explicit and matches what Story 1.3 does for `jekyll-seo-tag`. Netlify runs `bundle install` from `Gemfile.lock` with Ruby 3.4.11 (`netlify.toml`), so the lockfile change must be committed.
